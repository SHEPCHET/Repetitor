# ИС Репетитор

Программа для учёта учеников, родителей, направлений обучения, занятий и оплат.
Интерфейс — Tkinter, база данных — SQLite. Дополнительные пакеты не нужны.
Проверено на Windows с Python 3.15.0 и SQLite 3.53.4.

## Запуск нового проекта

Открой папку проекта в VSCodium. В его терминале выполни:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe init_db.py
.\.venv\Scripts\python.exe main.py
```

При первом запуске зарегистрируй учётную запись. Дальше запускай только `main.py`.
Git для запуска программы не требуется.

## Обновление существующего проекта

Закрой программу. Скопируй содержимое архива обновления в папку проекта
с заменой файлов кода. Существующие `repetitor.db`, `.venv`, `reports`,
`backups` и файл сохранённого входа сохраняются. В архиве нет базы данных,
паролей, ключа входа и папки окружения. Создавать новую базу не нужно.

## Основные действия

- **Ученики** — добавление и изменение карточек, родители, предметы, цели и тарифы,
  поиск по ФИО или ID, архив и восстановление. Предмет вводится вручную.
- **Расписание** — выбор недели и половины дня, создание, перенос и отмена занятий,
  просмотр отменённых, восстановление. Оплата доступна в меню занятия.
- **Занятия** — проведённые и запланированные занятия, поиск, архивные ученики,
  просмотр оплаты и изменение тем проведённых занятий.
- **Оплаты** — история поступлений и баланс учеников. Начислено — сумма стоимости
  проведённых занятий; получено — сумма оплат. Положительная разница — долг,
  отрицательная — переплата.
- **Отчеты** — выбор ученика и периода, предпросмотр, сохранение в TXT.
- **Настройки** — сведения об учётной записи, смена пароля, ручная копия и выход.

Стоимость хранится в целых копейках. Изменение тарифа в карточке ученика не
пересчитывает уже сохранённые занятия. Одна оплата покрывает полную стоимость
конкретного занятия; повторная оплата блокируется.

## Сохранённый вход

После первого успешного входа программа запоминает аккаунт на этом компьютере.
При следующем запуске открывается главное окно. Обычное закрытие программы
сохраняет вход; кнопка «Выйти из учётной записи» отменяет его и открывает форму
входа. После этого можно войти под другим логином.

Файл `.login_session.json` содержит случайный ключ, а не пароль. Он исключён
из Git. В таблицу `users` автоматически добавляется поле для проверки ключа;
новая таблица не создаётся, существующие данные сохраняются. Базу пересоздавать
не нужно. Повреждённый ключ или удалённый аккаунт приводят к обычной форме входа.
При смене пароля в Настройках ключ обновляется; прежний ключ больше не подходит.
Если сохранить вход не удалось, программа сообщает об этом и позволяет работать
после обычной проверки логина и пароля.

## Резервные копии

После входа или успешной регистрации обычное закрытие окна создаёт новую копию
в папке `backups` рядом с базой. Выход из учётной записи не отменяет эту копию:
она создаётся при последующем закрытии программы. Без входа и регистрации
копия не создаётся. Ручная кнопка в Настройках работает отдельно.

Существующие копии не перезаписываются и автоматически не удаляются.
Если копию записать не удалось, можно повторить попытку либо нажать «Отмена»:
программа останется открытой. При отказе закрыть журнал с несохранёнными темами
закрытие и копирование не выполняются. Автоматическая копия относится к обычному
закрытию приложения; принудительное завершение процесса её не запускает.

Чтобы восстановить данные:

1. Закрой программу.
2. Сохрани текущий `repetitor.db` отдельно под другим именем.
3. Скопируй выбранную исправную копию из `backups` в папку программы.
4. Дай скопированному файлу имя `repetitor.db`.
5. Запусти программу и проверь карточки, расписание и оплаты.

## Проверки

В терминале папки проекта:

```powershell
.\.venv\Scripts\python.exe -B -X utf8 run_checks.py
```

Проверки используют временные базы с вымышленными данными. Рабочая база не
открывается и не изменяется. Результаты проверки этой версии — в `CHECKS.md`.

Код запуска программы находится в `main.py`; файлы с окончанием `_view.py`
описывают экраны, `_service.py` — правила работы, `_repository.py` — запросы к
базе. `init_db.py` создаёт структуру базы, `database.py` подключается к ней и
делает копии. Файлы `check_*.py` — прежние ручные проверки, они могут добавлять
данные; для автоматической проверки используй `run_checks.py`.
